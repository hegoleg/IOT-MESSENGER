# Решения и ограничения

## Решения

### Единый контракт
`PROTOCOL.md` + `shared/types.ts` — источник правды. Любое поле сначала там,
потом в коде. Это защищает сервер, PWA и прошивку от расхождений.

### Плоский JSON ≤ 1024 байт
Короткие ключи (`v`, `type`, `id`, `from`, `ts`, `text`, `kb`, `t`, `d`) и
жёсткий лимит пакета выбраны ради ESP8266: меньше heap и фрагментации.

### API в стиле FastBot
`IoTBot bot(TOKEN)`, `attach`, `tick`, `sendMessage`, `sendInline`,
`editMessage`. Миграция с Telegram-ботов — замена заголовка и токена.

### Релей без логики
Сервер только маршрутизирует `dev` ↔ `usr`, хранит 50 сообщений и отдаёт
историю. Бизнес-логика остаётся на плате.

### Токен = идентичность
Один токен на устройство; PWA входит по нему. Токены выдаёт релей.
`ADMIN_KEY` опционален для создания устройств.

### Настройка из браузера
Quickstart-прошивка не содержит секретов. Сайт через Web Serial сканирует
Wi-Fi, создаёт токен и отправляет конфиг; плата хранит его в EEPROM.

### Один билд для сайта и PWA
`build:site` собирает лендинг и PWA, база PWA задаётся `SITE_BASE`.
GitHub Pages использует `/IOT-MESSENGER/`, Netlify — корень.

### GitHub Pages через `gh-pages`
Workflow собирает сайт и пушит в `gh-pages`; Pages публикует ветку. Это
обходит ограничения `deploy-pages` и даёт контроль над артефактом.

### Как в Telegram: релей
В Telegram клиенты сами подключаются наружу к серверам Telegram. У нас так же:
ESP и PWA идут на релей. Поэтому не нужны публичный IP платы, проброс портов
и не мешает CGNAT. ESP-сервер (`IoTBotLAN`) — для одной Wi-Fi; прямой доступ
к ESP — опция при наличии публичного IP.

### Админ-API за `ADMIN_KEY`
`GET /api/v1/devices`, `DELETE /api/v1/devices/:token` и
`GET /api/v1/metrics` включены всегда, но требуют `ADMIN_KEY`. Если ключ не
задан, они отвечают `401`: это безопасный дефолт — админка не открывается
случайно на публичном сервере.

### Профили — локальные
Аккаунтов на сервере нет, поэтому профили сделаны в `localStorage`: у каждого
свои устройства, адрес релея, режим и флаг онбординга. Первый профиль
(`default`) оставил старые ключи — существующие установки не теряют данные.
Такой профиль делит экран «на несколько хозяев» в одном браузере, но не
синхронизируется между устройствами.

### Флешер на концепт-странице
`/preview/index.html` — статичный файл, Vite его не обрабатывает. ESP Web
Tools и генератор QR подключаются с CDN, а пути к манифесту и приложению
относительные (`../firmware/…`, `../app/`), чтобы страница работала и на
Netlify, и в подпапке GitHub Pages.

## Ограничения

- **Железо не проверено:** прошивка, LAN-сервер и serial-настройка ждут реальной платы.
- **LAN-режим:** реализован в `IoTBotLAN` (порт 81 + mDNS); PWA умеет
  подключаться напрямую, но с HTTPS-страницы браузер может блокировать
  `ws://` как mixed content.
- **Полный self-host на ESP:** PWA-статика, HTTPS/WSS и проброс порта пока не
  входят. Из другой сети без публичного IP нужен релей или туннель.
- **Web Push:** заглушка на сервере, подписок в PWA нет.
- **Presence:** опрос раз в ~30 секунд; для десятков устройств нужен
  мультиплексированный presence на сервере.
- **Авторизация:** только bearer-токены; ролей и пользователей нет.
- **Профили:** локальные, в `localStorage` этого браузера. Между устройствами
  не синхронизируются; очистка сайта теряет список устройств (токены живы).
- **Шифрование:** SQLite и EEPROM не шифруются; Wi-Fi-пароль в EEPROM открыт.
- **Сертификаты:** `beginSSL` без fingerprint не проверяет сертификат.
- **Браузер:** прошивка из браузера — только Chrome/Edge, HTTPS, не iOS.
- **Лицензия:** не выбрана; `library.json` указывает MIT только для библиотеки.
- **Один релей:** общая история возможна только через один экземпляр сервера.

## Безопасность

- `.env`, `secrets.h`, базы и реальные токены не коммитить.
- Токен — bearer-секрет: история и управление устройством доступны любому,
  кто его знает.
- CORS на сервере открыт; для продакшена стоит ограничить origin.
- Rate limit — 20 сообщений в минуту на соединение по умолчанию.
- Публичный репозиторий не содержит секретов; это проверено перед публикацией.
