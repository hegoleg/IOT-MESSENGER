# Ошибки и решения

| Симптом | Причина | Решение |
| --- | --- | --- |
| Netlify: `Cannot find module @iot/shared` | `shared` не собран до PWA | `build:site` сначала собирает `@iot/shared`; проверьте порядок в `scripts/build-site.mjs` |
| GitHub Pages 404 | репозиторий был приватным или Pages выключен | публичный репозиторий + Pages source `gh-pages` |
| `/app/` 404 | задеплоен только лендинг | `npm run build:site`; PWA должна лежать в `landing/dist/app` |
| PWA на Pages: ассеты 404 | неверный `SITE_BASE` | `SITE_BASE=/IOT-MESSENGER/ npm run build:site` |
| PWA на Netlify: ассеты 404 | лишний `SITE_BASE` | собирать без `SITE_BASE` (корень `/app/`) |
| `npm: command not found` | нет Node.js | установить Node 20+, открыть терминал заново |
| `pio: command not found` | нет PlatformIO | установить PlatformIO, либо `python -m platformio` |
| Плата не прошивается | драйвер/кабель/порт | CH340/CP210x, кабель с данными, правильный порт |
| Web Serial недоступен | Firefox/Safari/iOS или HTTP | Chrome/Edge, HTTPS или localhost |
| ESP8266 не видит Wi-Fi | сеть 5 ГГц | использовать 2,4 ГГц |
| Плата не подключается к релею | `localhost` в `secrets.h` | указать IP компьютера с релеем |
| Плата не подключается | порт/файрвол/токен | открыть 8080, проверить токен и сеть |
| PWA «не в сети» | неверный адрес релея | настройки → адрес релея → проверить |
| PWA не видит плату по LAN | телефон и плата в разных сетях или включена изоляция клиентов | одна сеть 2,4 ГГц, отключить AP isolation |
| Из другой сети плата не открывается | нет публичного IP или порт закрыт | проброс порта 81, DDNS, проверить CGNAT |
| Провайдер CGNAT | входящие соединения запрещены | релей/туннель или публичный IPv6 |
| HTTPS-страница не подключается к плате | mixed content `ws://` | открыть PWA по `http://` или поднять WSS с сертификатом |
| LAN: браузер блокирует `ws://` | HTTPS-страница + mixed content | открыть PWA локально по `http://` или разрешить local network в браузере |
| mDNS `iotbot-xxxx.local` не резолвится | сеть/ОС блокирует multicast | подключиться по IP из Serial-лога |
| LAN: `err` 401 | неверный `LAN_TOKEN` в URL | сверить токен в `secrets.h` и PWA |
| Порт 81 занят | другая служба на плате | изменить порт в `IoTBotLAN(token, port)` и в PWA |
| Токен недействителен | база релея пересоздана | создать новое устройство |
| QR не открывает приложение | ссылка `/app/` неверна | `data-app-url` или `SITE_BASE` |
| Старая версия PWA | service worker/кэш | hard reload, очистить кэш, autoUpdate |
| `port is already open` (USB) | окно прошивки держит порт | закрыть ESP Web Tools и подключиться снова |
| Netlify «Team protection» | защита доступа включена | Access & security → выключить/дать доступ |
| `npm run build:site` на Windows: `spawnSync npm.cmd EINVAL` | запуск npm.cmd | исправлено через `npm_execpath` в `scripts/build-site.mjs` |
| Pages workflow в очереди | GitHub Actions занят | подождать или запушить `landing/dist` в `gh-pages` вручную |
| Битая кириллица в PowerShell | кодировка консоли | Windows Terminal или `chcp 65001` |
| SQLite `database is locked` | два процесса/сеть | один релей, локальный диск |

## Диагностика

- Релей: `curl https://host/api/v1/health`.
- История: `curl "https://host/api/v1/history?token=..."`.
- WebSocket: `wscat -c "wss://host/ws?role=usr&token=..."`.
- Прошивка: `pio device monitor -b 115200`, искать `IOTBOT:READY`.
- PWA: DevTools → Application → Service Workers / Manifest.
- Сайт: DevTools → Network, проверить `/app/` и `/firmware/manifest.json`.
