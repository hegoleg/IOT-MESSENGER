# Прошивка

Каталог: `firmware/`. C++-библиотека **IoTBot** с API в стиле FastBot для
ESP8266 и ESP32.

## API

```cpp
#include <IoTBot.h>

IoTBot bot(BOT_TOKEN);

void onMessage(IB_msg &msg) {
  if (msg.isCallback && msg.data == "pump_on") {
    bot.editMessage(msg.id, "Полив включён");
  }
}

void setup() {
  bot.setServer(SERVER_HOST, SERVER_PORT, SERVER_SECURE);
  bot.attach(onMessage);
}

void loop() {
  bot.tick();  // неблокирующий
}
```

`IB_msg`: `text`, `data`, `id`, `isCallback`.

Методы: `sendMessage`, `sendInline(text, menu)`, `editMessage(id, text)`,
`editMessage(id, text, menu)`, `isConnected`.

## Меню

`\n` — новый ряд, `\t` — кнопка. Пары `"Текст:data"`; без `:` data
генерируется (`b0`, `b1`, …). Максимум 3×3.

## Память

- статический TX-буфер 1024 байта;
- ArduinoJson v7, переиспользуемые документы;
- нет `delay()` и блокирующих вызовов в библиотеке;
- текст обрезается UTF-8-safe до 512 байт;
- пакет >1024 байт не отправляется.

## Настройка quickstart по USB

Плата без секретов в прошивке. Сайт отправляет по serial:

| Команда | Ответ |
| --- | --- |
| `IOTBOT:WHO` | `IOTBOT:HELLO:<chip>:v1:<setup\|configured>` |
| `IOTBOT:SCAN` | `IOTBOT:NETWORKS:["ssid1","ssid2"]` |
| `IOTBOT:SET:{...}` | `IOTBOT:OK`, сохранение в EEPROM, перезагрузка |
| `IOTBOT:RESET` | `IOTBOT:OK`, очистка, перезагрузка |

`SET` принимает `{ssid, pass, token, host, port, secure}`. Wi-Fi-пароль
хранится в EEPROM в открытом виде — это локальная память платы.

## Бинарники для сайта

```bash
cd firmware/examples/quickstart
pio run -e nodemcuv2 -e esp32dev
cd ../../..
npm run firmware:export
```

Скрипт собирает единый ESP32-образ через `esptool merge-bin` и кладёт
`esp8266.bin`, `esp32-merged.bin`, `manifest.json` в
`landing/public/firmware/`.

> [!warning] Аппаратная проверка
> Прошивка из браузера и USB-настройка реализованы, но не проверены на живой
> плате в текущем окружении. Нужен прогон на реальном ESP8266/ESP32.
