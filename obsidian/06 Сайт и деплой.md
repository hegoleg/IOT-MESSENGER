# Сайт и деплой

Каталог: `landing/`. Промо-лендинг в стиле «технический даташит»: бумага,
сетка, графит, кислотный лайм.

## Секции

1. Hero с макетом чата.
2. Возможности.
3. Сравнение с Telegram Bot API.
4. Как работает + схема.
5. Прошивка из браузера (ESP Web Tools + Web Serial).
6. Код C++/JSON.
7. Быстрый старт с пояснением каждой команды.
8. Спецификации.
9. FAQ.
10. Установка PWA.
11. CTA и футер.

## Сборка

```bash
npm run build:site
```

Скрипт `scripts/build-site.mjs`:

1. собирает `@iot/shared`;
2. собирает лендинг (`--base=./`);
3. собирает PWA с `APP_BASE` из `SITE_BASE`;
4. копирует PWA в `landing/dist/app`.

База:

- `npm run build:site` → PWA `/app/` (Netlify, свой домен в корне);
- `SITE_BASE=/IOT-MESSENGER/ npm run build:site` → PWA
  `/IOT-MESSENGER/app/` (GitHub Pages).

## GitHub Pages

- Репозиторий публичный.
- Pages source: ветка **`gh-pages`**.
- Workflow `.github/workflows/deploy-gh-pages.yml` на push в `main` собирает
  сайт с `SITE_BASE=/IOT-MESSENGER/` и пушит `landing/dist` в `gh-pages`
  (peaceiris/actions-gh-pages, `force_orphan`).
- Ветку `gh-pages` вручную не редактировать.

Живые адреса:

- https://hegoleg.github.io/IOT-MESSENGER/
- https://hegoleg.github.io/IOT-MESSENGER/app/
- https://hegoleg.github.io/IOT-MESSENGER/preview/ — концепт лендинга друга
  (файл `landing/public/preview/index.html`, основной лендинг не затронут)

## Netlify

- `netlify.toml`: `npm run build:site`, publish `landing/dist`.
- Сборка без `SITE_BASE` → PWA `/app/`.
- Подключён к GitHub, обновляется на push, умеет Deploy Preview для PR.

Живые адреса:

- https://brilliant-kashata-2a9cd6.netlify.app/
- https://brilliant-kashata-2a9cd6.netlify.app/app/

## Прошивка

- `landing/public/firmware/manifest.json` и бинарники ESP8266/ESP32.
- ESP Web Tools требует Chrome/Edge и HTTPS.
- После прошивки сайт настраивает Wi-Fi и токен по USB.
- QR ведёт в PWA с токеном и адресом релея.

## Ссылка на PWA

По умолчанию `data-app-link` вычисляет `./app/` относительно страницы. Для
отдельного домена задайте `data-app-url="https://app.example.com/"`.

## Деплой релея

GitHub Pages/Netlify не запускают Node.js. Релей (`server/dist/index.js`)
поднимается отдельно (VPS, домашний ПК) и проксируется на `/api` и `/ws`.
Адрес релея вводится в PWA или приходит в QR.

Если у провайдера есть публичный IP, релей не обязателен: ESP доступна
напрямую через проброс порта и DDNS. Статику PWA в перспективе можно отдавать
с самой платы (LittleFS) — тогда сайт и WebSocket живут на одном хосте.
