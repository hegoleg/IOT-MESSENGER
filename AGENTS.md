# Project Rules & Architecture Guide for AI Agents

Ты работаешь над проектом IoT-Messenger — легким аналогом Telegram-ботов для микроконтроллеров ESP8266 и ESP32, работающим без блокировок, VPN и сложных настроек.

## 1. Структура монорепозитория

/
├── AGENTS.md           # Правила проекта (этот файл)
├── PROTOCOL.md         # Единый контракт JSON-протокола (Source of Truth)
├── shared/
│   └── types.ts        # Общие TypeScript-типы, строго зеркалящие PROTOCOL.md
├── server/             # Релей-сервер (Node.js + TypeScript + Fastify + ws + SQLite)
├── firmware/           # C++ библиотека IoTBot (в стиле FastBot) для ESP8266 / ESP32
└── web-app/            # Мобильный PWA-клиент (React + Vite + TypeScript + Tailwind CSS)
## 2. Единый источник правды (Single Source of Truth)
* ЗАПРЕЩЕНО придумывать новые поля JSON-пакетов или менять названия ключей в коде сервера, прошивки или фронтенда без предварительного обновления PROTOCOL.md и shared/types.ts.
* Модули server/ и web-app/ обязаны импортировать типы пакетов напрямую из shared/types.ts.

## 3. Требования к модулям

### 3.1 firmware/ (C++ для PlatformIO / Arduino)
* Целевые платформы: espressif8266 и espressif32.
* **Синтаксис API обязан повторять FastBot**, чтобы миграция с Telegram-ботов сводилась к замене заголовочного файла и токена:
  * IoTBot bot("TOKEN");
  * bot.attach(callback_function); — обработчик принимает структуру IB_msg& msg (msg.text, msg.data, msg.isCallback, msg.id).
  * bot.tick(); — строго неблокирующий вызов в loop().
  * bot.sendMessage(text);
  * bot.sendInline(text, menu_string); — поддержка компактного синтаксиса меню (например, "Кнопка 1 \t Кнопка 2 \n Кнопка 3" с автоматической генерацией callback_data или пар вида "Текст:data").
  * bot.editMessage(id, text);
* Жесткие правила по памяти:
  * Никаких блокирующих delay() внутри библиотеки.
  * Избегать фрагментации кучи на ESP8266: использовать ArduinoJson v7 с контролем размера буфера (до 1024 байт) и минимизировать динамическую конкатенацию String в цикле.
  * В библиотеке должна быть папка examples/ с готовым рабочим скетчем (управление реле + опрос датчика + инлайн-кнопки).

### 3.2 server/ (Релей-сервер)
* Стек: **Node.js (v20+), TypeScript, Fastify, ws, better-sqlite3**.
* Сервер не выполняет пользовательскую логику — он выступает как быстрый маршрутизатор между role=dev и role=usr по token, хранит историю последних 50 сообщений на токен в SQLite и отдает REST-эндпоинт GET /api/v1/history?token=... для загрузки истории при старте клиента.
* Предусмотреть простую генерацию новых токенов устройств (POST /api/v1/devices/create).

### 3.3 web-app/ (PWA-клиент)
* Стек: **React 19, Vite, TypeScript, Tailwind CSS, lucide-react**.
* Интерфейс mobile-first в стиле современного мессенджера:
  * Список добавленных устройств (с индикатором online / offline и добавлением по токену или QR-коду).
  * Экран чата: лента сообщений (слева — плата, справа — пользователь), рендер сетки инлайн-кнопок под сообщениями платы, поле ввода текстовых команд и быстрые /команды.
  * Поддержка переключателя режима: Облако (WebSocket) / Локальная сеть (прямой IP/mDNS).
  * Настроенный manifest.json и Service Worker для установки на экран смартфона как PWA.

## 4. Правила совместной работы и чистоты кода
1. Модульность: Не складывай весь фронтенд в один файл App.tsx. Разноси экраны и компоненты по отдельным файлам (DeviceList.tsx, ChatView.tsx, InlineKeyboard.tsx, AddDeviceModal.tsx), чтобы два разработчика могли параллельно работать без merge-конфликтов.
2. Проверка сборки: После написания или изменения кода в любом модуле обязательно проверяй компиляцию (npm run build в server/web-app или pio run в firmware).
3. Безопасность: Никогда не зашивай реальные токены, пароли или IP-адреса серверов в код — выноси настройки в .env (для сервера/веба) и secrets.h (в примерах прошивки, добавив его в .gitignore).
