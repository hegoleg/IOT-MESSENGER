01 / Возможности

Всё, что нужно
для IoT-мессенджера

Никаких тяжёлых SDK, облачных подписок и внешних посредников. Только плата, ваш релей и телефон.

01

FastBot-совместимый API

IoTBot bot(TOKEN), attach(), tick(), sendInline(). Миграция с Telegram-ботов — замена заголовка и токена.

bot.tick(); // неблокирующий
02

Облако и локальная сеть

WSS через релей из любой сети или прямое подключение к плате по IP/mDNS на порту 81. Один и тот же JSON-протокол.

wss://relay/ws · ws://ip:81
03

Кнопки и живые сообщения

Инлайн-клавиатура до 3×3, callback_data возвращается на плату. Показания датчиков обновляются через edit: true.

kb → [[{ t, d }]]
04

История в вашей SQLite

Релей хранит последние 50 сообщений на токен и отдаёт их при старте клиента. Данные не уходят третьим сторонам.

GET /api/v1/history?token=…
05

PWA вместо нативного клиента

Мобильное приложение ставится из браузера: список устройств, чат, инлайн-кнопки, quick-команды и офлайн-оболочка.

React 19 · Vite · Tailwind
06

Экономия памяти ESP

Плоский JSON, ArduinoJson v7, статический буфер 1024 байта. Никаких delay() внутри библиотеки.

RAM: 39% на NodeMCU

02 / Зачем

Свой протокол
вместо чужого API

Telegram удобен, но зависит от внешнего сервиса и доступности. IoT-Messenger ставится на ваш сервер и работает по открытому контракту.

Telegram Bot API

  • Внешний API и зависимость от доступности
  • В сети без прямого доступа нужен VPN или прокси
  • Ограничения платформы и очереди сообщений
  • Тяжёлые TLS-библиотеки на ESP8266

IoT-Messenger

  • Свой релей на вашем домене и сервере
  • Прямой WSS без посредников
  • Компактный пакет до 1024 байт
  • История и токены в вашей SQLite

03 / Как работает

Три шага
до первого сообщения

Релей, прошивка и клиент общаются по единому контракту PROTOCOL.md. Ни одного лишнего сервиса.

01

Получите токен

Токен — секретный код устройства. Его выдаёт релей одним запросом, и он же вставляется в PWA и secrets.h. 

# Windows: используйте curl.exe
curl -X POST \
  http://localhost:8080/api/v1/devices/create
# → {"token":"..."}
02

Прошейте плату

PlatformIO, secrets.h, токен и адрес релея.

cd firmware/examples/greenhouse
pio run -e nodemcuv2 -t upload
03

Откройте PWA

Добавьте токен по QR или вручную и отправьте /start.

npm run dev:web
# → http://localhost:5173

04 / Прошивка

Прошейте плату
из браузера

Chrome или Edge на компьютере, USB-кабель и плата ESP8266/ESP32. Wi-Fi, релей и токен настраиваются по USB — без PlatformIO и терминала. ESP8266 работает только в сетях 2,4 ГГц, прошивка — с компьютера.

Шаг 01 / Прошивка

Подключите плату по USB

Нажмите «Прошить», выберите порт и дождитесь окончания. Плата перезагрузится в режим настройки.

Web Serial недоступен. Откройте сайт в Chrome или Edge на компьютере по HTTPS. Разрешите доступ к USB-порту в браузере.

IoTBot Quickstart · ESP8266 / ESP32 · в диалоге нажмите Install и выберите порт

Шаг 02 / Настройка

Wi-Fi, релей и токен

Прошили плату? Подключите её по USB — сайт просканирует Wi-Fi сети, создаст токен и сохранит настройки на плате. Закройте окно установки перед подключением.

Для настройки по USB нужен Chrome или Edge на компьютере, HTTPS или localhost. Можно прошить вручную по быстрому старту.

Шаг 03 / Готово

Токен устройства

Наведите камеру телефона — приложение откроется с токеном. Или отсканируйте QR внутри приложения.

05 / Код

Знакомый синтаксис.
Открытый протокол.

Код на плате почти не отличается от FastBot. На проводе — плоский JSON, который легко читать и отлаживать.

FIRMWARE / C++ 
#include <IoTBot.h>

IoTBot bot(BOT_TOKEN);

void onMessage(IB_msg &msg) {
  if (msg.isCallback && msg.data == "pump_on") {
    bot.editMessage(msg.id, "Полив включён");
  }
}

void setup() {
  bot.setServer(SERVER_HOST);
  bot.attach(onMessage);
}

void loop() {
  bot.tick();  // неблокирующий цикл
}

06 / Быстрый старт

Разверните
за один вечер

Ниже — полный путь: от установки до первого сообщения. Писать код не нужно: только команды и четыре строки в secrets.h. Каждый шаг объяснён, а если платы нет — есть симулятор.

Что понадобится

  • Node.js 20+ для релея и PWA
  • PlatformIO для прошивки платы
  • ESP8266 / ESP32 и USB-кабель
  • Wi-Fi плата и телефон в одной сети

Команды выполняются в терминале: PowerShell в Windows, Terminal в macOS/Linux. Копируйте строки по одной и нажимайте Enter.

01 / Компьютер или сервер

Где: в папке проекта на компьютере с Node.js · два окна терминала 

# 1. один раз: скачать зависимости проекта
npm install

# 2. окно терминала №1: запустить релей
npm run dev

# 3. окно терминала №2: запустить PWA
npm run dev:web

# 4. выдать токен устройству
# Windows: вместо curl используйте curl.exe
curl -X POST http://localhost:8080/api/v1/devices/create
# ответ: {"token":"..."} — скопируйте токен
npm install
Скачивает библиотеки проекта. Нужен интернет, выполняется один раз.
npm run dev
Запускает релей на порту 8080. Окно терминала не закрывайте.
npm run dev:web
Запускает PWA на порту 5173. Откройте адрес из терминала в браузере.
curl …
Создаёт устройство и печатает токен. В Windows вызывайте curl.exe: PowerShell может подменять curl своей командой.
02 / Плата ESP

Где: в папке проекта на компьютере с PlatformIO · плата по USB 

cd firmware/examples/greenhouse
cp include/secrets.h.example include/secrets.h

# откройте include/secrets.h и заполните:
# WIFI_SSID  — имя вашей Wi-Fi сети
# WIFI_PASS  — пароль Wi-Fi
# BOT_TOKEN  — токен из шага 4
# SERVER_HOST — IP компьютера с релеем, например 192.168.1.10
# SERVER_PORT — 8080
# SERVER_SECURE — false для локального релея

pio run -e nodemcuv2 -e esp32dev   # проверить сборку
pio run -e nodemcuv2 -t upload     # прошить ESP8266
# для ESP32: pio run -e esp32dev -t upload
cd …
Переходит в папку с примером прошивки.
cp …
Создаёт файл настроек. В git он не попадёт — токен останется локальным.
secrets.h
Ваши Wi-Fi, токен и адрес релея. Важно: не localhost, а IP компьютера.
pio run
Собирает прошивку. Флаг -t upload сразу загружает её в плату.

Что должно получиться

В PWA появилось устройство со статусом «в сети», а на команду /start приходит меню с кнопками. Если нет — проверьте, что релей запущен, телефон и плата в одной Wi-Fi сети, а SERVER_HOST указывает на IP компьютера.

Нет платы? Запустите npm run sim:esp — симулятор создаст токен и будет отвечать на команды как ESP. Весь сценарий можно проверить ещё до прошивки.
Релей

08 / FAQ

Частые
вопросы

Коротко о том, что чаще всего спрашивают перед запуском.

Нужен ли VPN?

Нет. Вы поднимаете релей на своём сервере и подключаетесь к нему по WSS. Внешние API и посредники не используются.

Чем это отличается от Telegram-ботов?

Свой протокол и свой сервер. API намеренно повторяет FastBot: IoTBot bot(TOKEN), attach(), tick(), sendInline(), editMessage(). Миграция — замена заголовка и токена.

Где хранятся сообщения?

В SQLite на вашем релее: последние 50 сообщений на каждый токен. Клиент загружает историю через GET /api/v1/history?token=….

Хватит ли памяти ESP8266?

Да. Пакет ограничен 1024 байтами, текст — 512, JSON-документы переиспользуются, внутри библиотеки нет delay(). Сборка примера занимает около 39% RAM NodeMCU.

Что делать, если команда не найдена?

Проверьте установку: node -v должен показать версию 20 или новее, pio --version — версию PlatformIO. Если команда не найдена, установите Node.js и PlatformIO и откройте терминал заново.

Почему плата не подключается к релею?

В secrets.h укажите IP компьютера с релеем, а не localhost: плата не понимает localhost. Телефон и плата должны быть в одной Wi-Fi сети, порт 8080 — открыт, а токен — совпадать с тем, что введён в PWA.

Плата не прошивается. Что проверить?

Нужен кабель с передачей данных (не только зарядка), драйвер CH340/CP210x и правильный порт в PlatformIO. На Windows порт виден в «Диспетчере устройств», на macOS/Linux — в /dev/tty.*.

Можно ли подключить несколько плат?

Да. У каждого устройства свой токен и отдельная история. В PWA-клиенте они отображаются отдельными чатами.

Работает ли без интернета?

Протокол предусматривает LAN-режим: клиент подключается напрямую к ws://IP:81. Клиентская часть и контракт готовы; встроенный сервер на ESP — следующий этап прошивки.
