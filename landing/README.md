# Промо-сайт IoT-Messenger

Статический рекламный лендинг проекта. Без зависимостей и сборки для хостинга:
можно открыть `index.html` напрямую или раздать папку любым статическим сервером.

## Структура

```
landing/
├── index.html     # разметка и контент
├── styles.css     # «технический даташит»: бумага, сетка, сигнальный лайм
├── main.js        # мобильное меню, копирование кода, reveal-анимации
├── favicon.svg
└── dist/          # результат vite build (в git не попадает)
```

## Локальный просмотр

```bash
# из корня репозитория
npm run dev:landing      # http://localhost:5174
npm run build:landing    # только сайт, landing/dist
npm run build:site       # сайт + PWA в landing/dist/app
npm run preview:landing  # предпросмотр сборки
```

Либо просто откройте `landing/index.html` в браузере.

## Публикация

Содержимое `landing/dist` выкладывается на любой статический хостинг
(Cloudflare Pages, Netlify, nginx, GitHub Pages). Сборка использует
`--base=./`, поэтому сайт работает и в корне домена, и в подпапке.

Рекомендуемая схема: лендинг на `/`, PWA-клиент на `/app/`, релей на
`/api` и `/ws` того же домена. По умолчанию кнопка «Открыть приложение»
вычисляет ссылку `./app/` относительно текущего адреса. Для отдельного
домена задайте `data-app-url="https://app.example.com/"` у ссылок
`[data-app-link]` в `index.html`.

Для единого деплоя используйте `npm run build:site`: скрипт собирает лендинг
и PWA и копирует PWA в `landing/dist/app`. База PWA задаётся через
`SITE_BASE`:

- `npm run build:site` → PWA по `/app/` (Netlify, свой домен в корне);
- `SITE_BASE=/IOT-MESSENGER/ npm run build:site` → PWA по
  `/IOT-MESSENGER/app/` (GitHub Pages в подпапке).

Для GitHub Pages workflow `.github/workflows/deploy-pages.yml` собирает сайт
с нужным `SITE_BASE` и публикует при пуше в `main`. Для Netlify `netlify.toml`
делает сборку без `SITE_BASE`; он также удобен для Deploy Preview в pull
request.

## Установка приложения

Секция `#app` объясняет установку PWA: Android (Chrome → «Установить
приложение»), iPhone/iPad (Safari → «Поделиться» → «На экран Домой») и
компьютер (иконка установки в адресной строке). Внутри PWA есть мастер
настройки релея, поэтому терминал пользователю не нужен.

## Прошивка из браузера

Секция `#flash` использует ESP Web Tools и Web Serial:

1. Пользователь подключает плату по USB и прошивает готовый образ.
2. Сайт открывает serial-порт, просит плату просканировать Wi-Fi
   (`IOTBOT:SCAN`), создаёт токен через `POST /api/v1/devices/create`
   и отправляет настройки командой `IOTBOT:SET`.
3. Плата сохраняет конфигурацию в EEPROM, перезагружается и подключается к
   релею. Сайт показывает токен и QR-код для PWA.

QR-код содержит ссылку вида `/app/#token=...&relay=...`: камера телефона
открывает PWA, приложение сохраняет адрес релея, само добавляет устройство и
открывает чат. Тот же QR можно отсканировать внутри PWA при добавлении
устройства.

Требования: Chrome/Edge на компьютере, HTTPS или localhost. Прошивка
работает только с компьютера, установка PWA — с телефона.

Бинарники и манифест лежат в `public/firmware/`. Пересобрать их:

```bash
# из корня
cd firmware/examples/quickstart
pio run -e nodemcuv2 -e esp32dev
cd ../../..
npm run firmware:export
```

`firmware:export` собирает единый ESP32-образ через `esptool merge-bin` и
копирует файлы в `public/firmware/`. Адрес релея по умолчанию берётся из
текущего домена; для локальной проверки можно открыть
`?relay=ws://localhost:8080` или вписать адрес в поле.

> Аппаратная проверка прошивки и serial-настройки требует реальной платы
> ESP8266/ESP32; в текущем окружении проверены сборка, манифест и UI.
