# IoT Messenger — PWA-клиент

Мобильный клиент к релей-серверу IoT-Messenger. React 19 + Vite 8 + TypeScript + Tailwind CSS 4 + lucide-react.

## Возможности

- Мастер настройки при первом запуске: адрес релея, проверка соединения, создание устройства и установка PWA — без терминала.
- QR-ссылка из мастера прошивки (`/app/#token=...`) открывает приложение и автоматически добавляет устройство.
- Список устройств с online/offline-индикатором (фоновые проверки через релей) и последней активностью.
- Добавление устройства по токену, создание нового токена на релее прямо в приложении или сканирование QR-кода.
- Экран чата: сообщения платы слева, пользователя справа, инлайн-кнопки под сообщениями платы.
- Разделители дат («Сегодня», «Вчера»), кнопка прокрутки вниз, меню чата: настройки, копировать токен, очистить локальную ленту, изменить IP локального устройства.
- Поле ввода, быстрые команды и переключатель режима **Облако / Локально**.
- Настройки релея и установка приложения доступны из шапки; адрес сохраняется в localStorage.
- Профили: несколько локальных профилей на одном устройстве — у каждого свой список устройств, адрес релея и режим подключения.
- Строгий интерфейс в тёмной палитре промо-сайта: тёплые чёрные `#0b0b0a…#302c25`, оранжевый акцент `#ff5a1f`, Inter Tight, моноширинные технические подписи, прямоугольные панели без градиентов.
- PWA: manifest и service worker (устанавливается на экран смартфона, работает офлайн для оболочки).

## Проверка без платы

```bash
# из корня: релей + симулятор ESP (токен создастся автоматически)
npm run dev
npm run sim:esp -- --telemetry=5
```

Симулятор печатает токен — добавьте его в PWA и отправьте `/start`, `/on`,
`/off`, `/status`, `/stop` или нажимайте инлайн-кнопки.

## Запуск

```bash
# из корня репозитория
npm install
cp web-app/.env.example web-app/.env    # VITE_SERVER_URL=ws://localhost:8080
npm run build                            # shared + server + web-app
npm test                                 # юнит-тесты (vitest)
npm run dev:web                          # http://localhost:5173

# или из web-app/
npm run dev
npm run build
npm test
npm run preview
```

## Профили

Профили живут только в `localStorage` этого браузера — аккаунтов и
синхронизации на сервере нет (релей знает только токены устройств).

- Кнопка с инициалами в шапке открывает список профилей: переключение,
  переименование, удаление, создание нового.
- Первый профиль — `Основной` (id `default`). Он использует прежние ключи без
  префикса, поэтому установленные приложения не теряют устройства.
- Остальные профили хранят данные под префиксом `iotbot.p.<id>.…`:
  `iotbot.p.<id>.iotbot.devices.v1`, `.iotbot.serverUrl`, `.iotbot.onboarded`,
  `.iotbot.mode`.
- При удалении профиля его ключи стираются; удалить `Основной` нельзя.
- Логика — в `src/lib/profiles.ts`, интерфейс — `src/components/ProfilesModal.tsx`.
- Тесты: `src/lib/profiles.test.ts` (15 кейсов: скоупы, изоляция, миграция legacy-ключей).

## Деплой

- Лендинг + PWA в корне: `npm run build:site` → PWA по `/app/`.
- GitHub Pages в подпапке: `SITE_BASE=/IOT-MESSENGER/ npm run build:site`
  → PWA по `/IOT-MESSENGER/app/`.
- Публичный workflow: `.github/workflows/deploy-gh-pages.yml` (пушит в
  ветку `gh-pages`).

По умолчанию клиент подключается к тому же домену, где он размещён
(`ws(s)://<host>`); на локальных Vite-портах 5173/4173 используется
`ws://<host>:8080`. Значение можно переопределить через `VITE_SERVER_URL`.
При первом запуске открывается мастер настройки: адрес релея, проверка
соединения и создание устройства. Адрес можно изменить в настройках приложения
(иконка шестерёнки) — значение сохраняется в localStorage.
В облаке укажите `VITE_SERVER_URL=wss://your.server` как значение по умолчанию.

## Архитектура

```
src/
├── App.tsx                 # состояние: устройства, активный чат, режим, онбординг
├── components/
│   ├── AppHeader.tsx       # бренд, режим, настройки
│   ├── ModeSwitch.tsx
│   ├── Onboarding.tsx      # мастер настройки: релей → проверка → устройство
│   ├── SettingsModal.tsx   # адрес релея, установка PWA, повторный мастер
│   ├── DeviceList.tsx      # список устройств, пустое состояние
│   ├── DeviceCard.tsx      # карточка, статус, переименование, удаление
│   ├── AddDeviceModal.tsx  # добавление по токену, создание на релее
│   ├── QrScanner.tsx       # сканирование QR (камера, jsQR)
│   ├── ChatView.tsx        # экран чата, шапка, баннер соединения
│   ├── MessageBubble.tsx   # пузырь сообщения
│   ├── InlineKeyboard.tsx  # сетка инлайн-кнопок
│   ├── Composer.tsx        # ввод и отправка
│   └── QuickCommands.tsx   # быстрые /команды
├── hooks/
│   ├── useDevices.ts       # localStorage-хранилище устройств
│   ├── useDeviceChat.ts    # история + WebSocket + heartbeat
│   ├── usePresence.ts      # фоновые online/offline-проверки списка
│   └── usePwaInstall.ts    # beforeinstallprompt и установка
└── lib/
    ├── connection.ts       # транспорт (облако/локально), реконнект
    ├── serverApi.ts        # health, создание токена, нормализация URL
    ├── settings.ts         # адрес релея и флаг онбординга
    ├── clipboard.ts        # копирование с fallback
    ├── types.ts            # StoredDevice, режимы, статусы
    ├── env.ts              # VITE_SERVER_URL
    └── format.ts           # время, даты и усечение токена
```

Типы пакетов берутся строго из `@iot/shared` (зеркало `PROTOCOL.md`), новых полей клиент не придумывает.
